# 数据与适配约定

策略使用框架标准数据，供应商的字段名、证券编码和单位由 adapter 转换。
统一格式使策略可以复用，但不能让没有权限或没有覆盖的数据自动出现。

## 当前数据源

| 数据 | 内置来源 | 范围与前提 |
| --- | --- | --- |
| 证券列表、交易日历、日线及辅助字段 | Tushare | 沪、深、北；具体历史、ST、涨跌停、指数接口取决于账号权限 |
| 30 分钟历史 | BaoStock 分钟路径 | 沪深；历史回补起点为 2020-01-02，北交所分钟线需扩展 |
| 盘中实时行情 | 用户扩展或可选腾讯演示源 | 腾讯默认关闭，一次固定 30 天，至少 5 秒间隔、最多订阅 100 个标的 |

抓取适配层可以处理更多分钟粒度，但策略正式运行合同是日线和 30 分钟。
显式请求不支持的市场会失败，不能静默改周期或把缺口当停牌。

## 字段和单位

| 字段 | 含义 |
| --- | --- |
| `asset` | 证券代码，如 `000001.SZ`、`600519.SH`；指数接口也有 `index_code` |
| `date` | 日线的交易日；规范分钟数据为 bar 结束时刻，策略视图按接口使用 `frame`/`dt` 时间列 |
| `open/high/low/close` | 价格，元；是否复权取决于获取接口的明确参数 |
| `volume` | 成交量，手；一手为 100 股，委托数量通常使用股 |
| `amount` | 成交额，千元；不要直接当作元与账户现金相加 |
| `adjust` | 累计复权因子 |
| `is_st` | ST 标记 |
| `up_limit/down_limit` | 当日涨跌停价；必须保留缺失含义，不能自行统一推算为 10% |

Tushare 日线与腾讯行情的单位是规范口径；BaoStock 的股/元在组合抓取路径中转换为
手/千元。直接调用原供应商适配器时仍须确认其原始口径。
日线附带的 ST、限价和复权因子不是每个原始分钟响应都自带，按对应存储/视图补充，
不能只检查 OHLC 列存在就认为执行所需数据齐全。

## 时间与形成中的 bar

策略使用交易所时间，A 股按 `Asia/Shanghai` 理解。30 分钟的 `10:00` bar 表示
`09:30–10:00` 这一段；午休、节假日和下一交易日应使用交易日历，不能加固定自然时间。

历史接口可通过 `include_forming_bar` 明确是否包含正在形成的 bar。
盘中当前 bar 的 high/low/close 会变化；若策略需要已完成 bar，应显式关闭形成中 bar。
“记录属于某个交易日”也不意味着该记录在当日开盘就已可得。

## 复权

区分原始价格、前复权、后复权与真实账户成交价。内置 ML 因子计算接收原始日线，
在因子层按“原始价 × 累计复权因子”处理；不要先前复权后再重复乘因子。
策略历史查询的默认调整方式应以调用接口为准；成交和账户不能用复权价格替代真实价格。

## 完整性和失败

下载任务会检查覆盖、缺失 session 和内部分钟缺口。完整 bar 或明确停牌证据才能
关闭相应缺口；不凭空补零价或造平盘。源错误、限频和存储失败应在任务中报告。
BaoStock 请求有共享会话和持久化冷却，遇到冻结/限频不应反复重启以绕过。

添加历史源时实现 `DataFetcherPort`，声明数据集、市场、周期和历史能力，再在
抓取注册表中注册；实时源按[行情扩展](quote-extensions.md)接入。
新 adapter 先验证证券编码、日期、单位、复权、错误传播和缺失值，再用于策略。
