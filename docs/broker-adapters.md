# 自行适配交易柜台

HTTP 柜台接口的主要价值，是让用户可以接入自己的券商柜台，复用已有策略。
策略侧使用统一 Broker 合同，柜台侧负责与券商 SDK/协议交互；两端可以独立部署和维护。
不熟悉编程的用户，也可以把接口合同和验收用例交给 AI，协助生成并逐步验证适配器。

CE 提供本机独立 HTTP **模拟**柜台作为参考和验证环境，不开放真实交易。
真实券商适配需由 Millionaire 等宿主装配；安装一个适配器不会解除 CE 的实盘边界。

## 先理解两层适配

```text
策略 → Broker 接口 → HTTP 客户端/适配器 → 柜台服务 → 券商提供的 SDK/协议
```

如果柜台实现了与你的客户端约定相同的协议，策略代码可以继续沿用。
若券商响应字段、订单状态或接口不同，需在适配层转换；HTTP 本身不统一这些语义。
CE 独立模拟柜台不依赖 QMT；源码保留的 `GatewayClient` 是特定 gateway 协议客户端，
不能把它的全部端点当成任意券商必然支持的通用协议。

## 用模拟柜台学习和验证

按[模拟柜台教程](simulated-counter.md)启动进程。当前参考协议的主要端点：

| 请求 | 用途 |
| --- | --- |
| `GET /state` | 返回 `mode="simulated"` 与账户、订单和成交快照 |
| `POST /quotes` | 输入回放时刻与行情，让柜台自行撮合；只用于模拟验证 |
| `POST /orders` | 提交带 `client_order_id` 的买卖意图 |
| `POST /cancel` | 按订单标识撤销未成交余量 |

模拟客户端 `SimulatedBrokerAdapter` 只允许回环地址，并验证模拟标识。
真实券商柜台从自己的行情/交易回报产生事实，不应接受客户端传入“预期成交”冒充回报。

## 向 AI 提供哪些信息

提供券商官方接口文档、可用的测试环境、字段/单位、鉴权方式和错误码；不把真实凭据
写入生成的源码。要求 AI 先输出映射表，再实现转换：

- 证券代码、交易所、方向、数量单位、价格类型和交易时间。
- 订单提交、撤单、活动/历史委托、成交、持仓和资金查询。
- 订单 ID、稳定 `client_order_id`、部分成交和撤单余量的对应关系。
- 超时后如何查证是否已受理，以及重试时如何避免重复下单。
- 鉴权过期、限频、断线、进程重启、拒单与未知状态的处理。

可直接向 AI 这样描述任务：

> 根据我提供的 Broker 合同与券商测试接口，先列出逐字段及订单状态映射。
> 对尚无依据的字段明确标记，不要猜测。先在离线 fixture 和模拟柜台验证提交、
> 查询、部分成交、撤单、幂等及中断恢复，再给出宿主装配步骤。保留原策略逻辑和周期。

## 适配完成的判断

AI 生成的代码能导入或 HTTP 返回 200 还不够。用明确的初始资金、行情和手算结果，
核对订单、成交、现金、持仓、费用及重复提交行为；故意制造提交中断，验证先对账。
三模式接口测试提供参考，真实柜台的规则和网络回报还需独立测试环境验收。
下一版计划提供更系统的[自动审计](roadmap.md)，当前不声称 AI 生成适配器天然正确。
