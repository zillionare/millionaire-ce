# 仿真与持续运行

仿真使用当前行情和模拟账户运行策略，不会向券商发送真实订单。
同一策略可从回测沿用，账户现金、持仓和活动委托由 Paper Broker 管理和持久化。

## 从回测转入

1. 完成一份无失败状态的回测，核对周期、参数、费用和数据前提。
2. 在对应记录选择“转仿真”，弹窗中输入“仿真本金”，再确认。
3. 确认页面显示“已转入仿真”，在“系统维护 → 运行时监控”查看策略、账户、周期和状态。
4. 在仿真交易页面查看资金、持仓、委托和成交；从“系统维护 → 账号管理”管理模拟账户。

转入时会保留回测策略配置；本金是新仿真账户的起点，不是把回测末期的持仓和收益
复制为真实历史。CE 不提供“转实盘”；旧的实盘地址也不能启用真实交易。

## 行情是必要前提

历史数据够用不代表实时行情已经配置。默认腾讯源关闭，需选择一次 30 天演示或
接入[自己的行情扩展](quote-extensions.md)。检查最后行情时间、订阅证券和覆盖率。
没有新行情、休市、预热不足或尚未到执行窗口时，策略可能保持运行但不发出订单。

日线 ML 策略通常在收盘前的窗口决策；不要用盘中几分钟没有订单判断它失效。
30 分钟策略遵守自身周期。详细规则见[成交时序](execution.md)。

## 启停与恢复

只停某个策略，在“运行时监控”使用对应停止操作；停止策略不等于删除账户、
卖出持仓或撤销全部订单。涉及委托时检查账户中的实际状态。

需要维护整个服务时使用控制器或服务命令。关闭前台窗口只关闭控制器，后台策略仍可
运行。通过控制器停止服务后，持久化事实保留；启动时会恢复相关运行规格和账户，
对处理中意图先对账，不能把未知提交直接重新当新单发送。

服务重启后检查运行状态、行情新鲜度、待处理意图及账户对账结果，再判断恢复是否正常。
恢复机制不是对系统断电及所有未知故障都已验证的承诺，范围见[能力边界](scope.md)。

## 独立 HTTP 模拟柜台

普通仿真不要求另起 HTTP 柜台。需要验证 Broker 扩展和三模式接口时，使用
[独立模拟柜台](simulated-counter.md)。它是可单独重启和对账的进程，不连接 QMT，
也不会因启动该进程而让 CE 的实盘 UI 可用。
