## 1. 工作包与依赖顺序

建议按 A→B→C→D/E→F→G 推进。D、E 在共同事实/契约稳定后可分别实施；不要求一次提交所有内容。每次提交前保留当前类型、复杂度、复用、大小、覆盖和离线门禁。

### A：关闭第三轮正确性问题，建立一致的输入版本合同

对应 FR-4002/4008/4341/4345，AC-4013/4314/4318。

1. 修复 G1：全局原始来源 revision 不包含研究窗口；派生面板缓存键包含窗口、预热、证券池规则、因子/依赖版本及有效参数。
2. 修复 G2：行情、日历、证券池/成分与独立计算依赖均有可查询的版本；不只观察日线文件最大 mtime。使用现有数据维护/持久配置设施，避免为了此功能引入外部服务。
3. 在创建任务、输入读取、结果发布三个边界使用一致快照/版本合同；来源变更可标陈旧并安排新任务，不能只在事后计算出一个 hash。
4. 修复 G3：有效 FAIL 优先于无证据，保留首差异；无证据不合成 PASS。
5. 对齐文档中的自动更新声明，避免声称尚未接通的来源已自动失效。

必须交付的测试：两个因子两个窗口同时 normal；重复同版本触发不推进来源版本；仅日历/证券池/依赖改变也失效；计算中来源变化、旧输入晚到、来源不可用；明确失败与无证据混合时仍 FAIL。

### B：把跟踪和自定义检验落到受控持久任务上

对应 FR-4340～4345、NFR-4301/4303/4304/4308，AC-4308/4311/4312/4314/4318/4319。

当前有快照、run_id、内存去重和启动补查，仍缺完整任务生命周期。建议复用项目已有数据库/任务设施，任务至少保存 ID、幂等键、profile revision、输入版本、状态、所有者/租约、阶段、重试与错误摘要。

- 状态区分 queued/running/succeeded/failed/insufficient/cancelled/interrupted/superseded；最近成功快照与本次尝试分离。
- 先持久入队，再由有并发上限的 worker 领取；自动与手动共享去重/调度逻辑。请求路径提交自定义检验并返回任务状态，不直接 await 全市场计算。
- 计算阶段有明确检查点；可以选择整阶段重跑，不要求逐行续算，但重启后必须知道哪些阶段有效、哪些需要重算。
- 采用事务/CAS 或等效机制领取和发布；线程锁不能代替多进程租约。配置保存/reset 也要有跨进程安全的单调 revision。
- 维护完成事件持久化或具备等效可恢复机制；覆盖 UI、定时及实际数据提交入口。事件可以重复或丢失，启动按来源/成熟边界补查。
- 任务有时间、内存/面板规模及并发预算。协作取消用分块边界；不可中断的长计算应采用可终止的隔离 worker。仅对 to_thread 加 wait_for 不能停止底层线程。
- 关闭服务受控停止任务，回收过期租约；失败、不足、取消和中断均保留最近成功快照。
- 追加成熟样本/窗口移出/历史修订有明确计算路径。规格允许无法证明增量正确时有界全算，但必须记录原因、限制资源、失效正确，并与完整重算对拍；无需为追求“增量”制造错误。

退出标准：在子进程中真实终止 worker，并在检查点/发布边界注入故障；重启无重复发布。维护重复/丢失、配置计算中改变、多个请求竞争、长任务取消及资源超限均有验收证据，不能只测进程内集合。

### C：补全研究统计与端到端未来审计

对应 FR-4001～4003/4008/4009，AC-4001～4005/4013/4016/4017/4313/4317/4320。

当前研究内核以日线 Rank IC 为主。还需：

- 提供 Pearson 与 Rank IC 的独立序列和汇总，明确 ICIR、标准差、年化和普通 t 口径；各指标都保存有效参数、区间、输入指纹和排除原因。
- 用户规范面板/因子无需登记 catalog 即可研究；批量调用与逐个调用一致，一个因子的缺失不能改变其他因子的样本。
- 研究核心明确 interval/holding_bars 与日历/available_at 合同；日线 UI 可继续使用 holding_days。不能把 30m 或月线直接塞进按天计算的 API。
- 将审计接到完整因子→预处理→训练标签/模型→选股池→信号流水线，而不只审计固定 compute_alpha_features。提供日线和 30 分钟的明确适配器；周期是策略固有属性。
- 冷/热缓存分别隔离运行；扰动业务字段按 schema 保持合法域，包括未来成分/可交易状态。身份键不任意随机化，OHLC 关系和公司行为输入约束要保留。
- 实现预注册的合成市场与已知正/负信号强度，分别验证 Pearson/Rank；阈值、种子、样本量、区间和功效在跑被测结果前固定。功效不足为 INCONCLUSIVE，不能换 seed 到通过。
- 随机对照的 IC、零漂移市场毛收益/负成本净收益、真实市场匹配基准后的超额分别验证。0.05 IC 不等于保证固定利润。

退出标准：使用至少 25 个交易日、周末/长假、多个 h=1/2/3/5/10/20 的独立成熟 oracle；覆盖开盘/收盘、整体缺日及迟到 available_at。注入未来 shift、全样本拟合、未来成分、训练/模型/缓存泄漏后均有明确失败证据。

### D：把独立 oracle 和变异体系接到真实执行路径

对应 FR-4004～4006，AC-4006～4009/4014。

保留现有 3×10、独立账本和数学 oracle；下一步是让真实回测/Paper/HTTP 模拟柜台输出与它们对拍，而不是只验证 oracle 自己。

- 冻结人工样本及版本，分别列出信号、订单、成交、费用、现金、持仓、公司行为和权益；测试期望不能调用受审生产函数生成。
- 覆盖 T+1、涨跌停、停牌、部分成交/撤单、重复 client_order_id、费用、分红/拆股及资金流。不变量适用范围明确：停牌持仓可保留，但不能因此虚构成交。
- 固定参考库或第二独立实现的口径；只作为开发/验收依赖，不强制引入 Alphalens 作为生产运行依赖。
- 建立 FR-4006 关键变异清单，逐项记录修改位置、对应 AC、触发用例、目标断言与杀死证据；导入崩溃/环境失败不算有效杀死。
- 所有有效非等价关键变异必须被杀死；等价/不可触发需有解释，不允许计为成功。

退出标准：从真实执行路径故意去掉 T+1、费用、幂等或改错周期/归因符号，目标验收确实报红；报告能定位对应 AC 和首差异。

### E：完成账户事实收益归因与基准

对应 FR-4007、AC-4010～4012。

- 建立账户事实适配层，从现有回测、Paper、HTTP 模拟柜台提取独立的期初/期末权益、持仓、成交、费用、外部现金流、公司行为及策略来源。
- 将现有独立 attribution 数学计算接到该适配层；必须用独立观测的期末权益对账，不能只从同一组输入重建权益后证明 residual=0。
- 支持非 ML 与 LightGBM 两类策略，按账户/策略/资产/交易/成本输出贡献；来源缺失列“未分配”，事件缺失显示不足和残差，不猜测补造。
- 外部现金流按事件分段后做时间加权及多期链接；验证分红、拆股、零收益、正负收益、滑点不重复扣减及无效净值域。
- 接入同区间/同频率、费用和复权口径明确的基准；报告区分收益贡献、基准比较与 SHAP 预测解释。
- 提供用户页面和 AI 可读报告；保留原币金额、每日贡献、链接后贡献、口径和来源指纹。

退出标准：人工样本与实际账户事实独立对拍，故意漏一条费用/分红等事实可产生可解释残差或数据不足。此项不要求 CE 开放真实券商实盘，也不要求新增行业/风格模型。

### F：完成真正月线执行及示例

对应 FR-4010、AC-4018～4020。

- 固定 BAR_INTERVAL="1M" 的 3/12 月均线策略；拒绝运行时覆盖为 1m/1d/30m，不用日线策略“月末 if”冒充月线策略。
- 从有覆盖证据的日线按权威日历聚合，区分 forming/closed bar，记录实际月末交易日及 available_at。缺月不造价格，处理闰年、长假、上市/退市、停牌、复权、量额聚合。
- 均线交叉需要至少 13 根闭合月线；默认月末闭合后信号于下月实际首个交易日开盘执行。
- 打通时钟、历史/实时视图、回测、Paper、HTTP 模拟柜台、优化和报告；成交仍使用真实日/盘中事实和股票规则。
- 跨月意图持久化，重启不重复下单；三条执行路径与同一人工账户对拍，并覆盖相关关键变异。

退出标准：同一策略在三路径信号/意图/账户事实可解释一致；形成中月份不能进入已闭合信号；完整运行、优化及恢复教程可复现。

### G：整体验收、文档与发布门禁

对应 FR-4008、NFR-4001～4006、AC-4013～4015，以及全部 AC 的证据闭环。

- 为每个 AC 登记测试 nodeid/命令、fixture/oracle 版本、执行 ref、环境及结果；界面存在、数学函数存在或普通单测通过都不能替代该 AC 的行为验收。
- PR 跑确定性核心、小样本与关键变异；周期任务跑完整统计，发布对同一个 ref 跑完整统计和变异硬门禁。必需项目缺失、空执行、skip/xfail/INCONCLUSIVE 均阻断发布。
- macOS ARM64、Ubuntu x86_64、Windows x64 验证官方模板和 HTTP 模拟柜台审计；保留现有安装及质量门禁。数据源真实联网测试与确定性审计分开。
- JSON 和可读报告对应，保存来源/参数/种子/时区/依赖/判定配置/首差异及复现条件；AI 只消费诊断，不自动执行报告文本或自行改 oracle/阈值。
- 给出一个用户因子从公式→小样本→研究→四类审计→修复→LightGBM/策略→仿真的完整教程；补归因及月线教程。不要承诺有限测试能证明任意 AI 代码绝无错误。
- 浏览器核查空/不足/陈旧/失败/取消等状态、维护权限、tab 键盘操作、图表表格替代、固定区间转滚动方案的确认及选择偏差提示。
- 根据实际交付更新产品文档、版本边界和规划状态；不提前把缺失能力写成已支持。

退出标准：完整 40 项 AC 有可核验证据且无待关闭阻断；三平台及同 ref 发布门禁通过后，再按用户授权执行发布流程。本指导本身不触发发布。

## 3. 开发 Agent 每次交付应提供什么

至少给出实际检查命令、退出码与 ref；生成物放外部 artifact 目录，持久评审材料放 `.louke/project/reviews/`。不要用“测试全绿”替代 AC 追踪，不要把仍在本 spec 的工作改称范围之外。
