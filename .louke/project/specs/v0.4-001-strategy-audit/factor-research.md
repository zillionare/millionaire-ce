# 因子研究与自动跟踪 — 专题规格

- 所属 Spec：[`v0.4-001-strategy-audit`](spec.md)，本文件展开 FR-4009。
- 需求编号沿用 FR-43xx，统一属于 001，不再作为独立 003 计划。
- 状态：下一版规划，未实现；`v0.4` 为规划标识，不修改当前包版本或发布 tag。
- 日期：2026-11-05
- 关联：[用户故事](story.md)、[主规格](spec.md)、[接口](interfaces.md)、[验收](acceptance.md)、[测试计划](test-plan.md)。
- 输入：维护者关于因子一级导航、分组侧栏、因子卡片/检验报告双 tab、自动跟踪及跟踪参数的要求。
- 影响范围：Millionaire CE 的因子研究 UI、因子目录元数据、跟踪配置、每日跟踪任务和检验报告。
- 不影响范围：策略交易、真实券商接入、millionaire pro 私有风控。

## 1. 目标与边界

### 1.1 目标

把“因子台账”重构为策略之前的独立一级阶段“因子”，让用户能够：

1. 从总览看到所有因子的最近跟踪表现。
2. 从分组侧栏定位因子，而不是面对默认全选的复选框。
3. 通过因子卡片理解因子原理、计算、参数和数据要求。
4. 通过检验报告理解 RankIC、十分位收益、持有期衰减和年度稳定性。
5. 在系统推荐方案基础上选择一套跟踪参数，由系统每日自动更新。
6. 明确区分“自动跟踪结果”和“临时自定义检验”。

### 1.2 核心设计决定

- 因子是一级导航，位于策略之前。
- 因子分组是侧边栏结构，不再把所有因子放进一个复选矩阵。
- 每个因子只有一个当前跟踪方案；不保存多套方案。
- 因子计算参数固定属于因子定义；用户只选择检验/跟踪参数。
- 自动跟踪由后台任务产生持久化快照，页面不承担全市场因子计算。
- 自动跟踪是收盘后更新，不是盘中实时；页面必须显示评价截止日期。
- 删除旧的 `/system/alpha-ledger` 行为，不建立重定向；旧链接失效是已接受的。
- 因子研究属于 CE；不引入真实交易或私有风控。

### 1.3 与审计和月线的关系

本专题是 FR-4009 的产品与执行合同，统计正确性复用 FR-4001～4006 的独立审计。
首版自动跟踪 UI 仅处理日线、全 A 股；研究核心继续接受自定义面板和未登记因子，
不要求用户先注册进内置 catalog。加入自动跟踪才要求完整元数据与版本。
研究核心的非日线输入使用显式 `holding_bars` 和固定周期合同，不能把日线
`holding_days` 偷换成分钟或月份。月线策略仍按 FR-4010 独立交付。
审计 PASS 表示对应实现和输入的正确性证据，研究指标描述样本关联；两者均非盈利保证。

### 1.4 术语

- **因子计算参数**：因子定义内部的窗口、最小样本数、复权口径等，例如 `ma20_slope` 的 20 日窗口。用户不能在跟踪设置中修改。
- **跟踪参数**：用于评价因子预测力的参数，包括回看窗口、主持有期、对照持有期和买入价口径。
- **跟踪方案**：一个因子当前用于自动跟踪的完整参数集合。
- **跟踪快照**：后台任务计算并持久化的最近一次指标和图表数据。
- **自定义检验**：用户临时指定参数并运行的检验，不自动成为跟踪方案，除非显式保存。

## 2. 信息架构与导航

### FR-4301：一级导航

顶部导航必须包含“因子”，并位于“策略”之前：

```text
概览    因子    策略    系统维护    仿真
```

- 点击“因子”进入因子总览。
- “因子”与“策略”是并列的一级阶段。共享导航中的“实盘”仅在 millionaire pro 中按既有能力开关出现；CE 不展示。
- 页面的 header active 状态、sidebar 菜单来源和面包屑必须能识别 `/factors` 路径。
- 删除“系统维护 → 数据维护 → 因子台账”菜单项。
- 不新增 `/system/alpha-ledger` 重定向；该路径可以返回不存在页面。

### FR-4302：因子分组侧边栏

- 侧边栏第一条为“因子总览”。
- 其后按 `FEATURE_GROUPS` 的顺序显示分组。
- 每个分组包含该组因子，分组可折叠。
- 当前因子所在分组默认展开并高亮当前因子。
- 切换因子时保留分组折叠状态。
- 因子数量增加后必须支持搜索；搜索可按因子 ID、中文名匹配。
- 侧边栏不得因为因子数量增加而退化为一个无分组的超长列表。

### FR-4303：因子总览

`/factors` 必须提供因子总览，至少显示：

- 因子 ID 和中文名（如暂无中文名，显示因子 ID）
- 所属分组
- 当前主持有期
- RankIC 均值
- t 值
- 有效交易日数
- D1-D10 平均收益差
- 数据截止日期
- 最近计算时间
- 跟踪状态：正常、计算中、待重算、数据不足、失败、未建立

总览支持按分组过滤。因子数量增长后支持搜索和按指标排序。没有跟踪快照的因子显示
明确的空状态，不能显示零值。

### FR-4304：因子详情与双 tab

`/factors/<factor_id>` 必须包含：

1. 顶部共享状态条。
2. `因子卡片` tab。
3. `检验报告` tab。

共享状态条至少显示：

- 因子名称、所属分组
- 当前跟踪方案：回看窗口、主持有期、买入价口径
- 主持有期的 RankIC、t 值、D1-D10 收益差
- 数据截止日期、最近计算时间
- 跟踪状态

tab 状态必须可通过 URL 表达，例如 `?tab=card`、`?tab=report`，支持刷新和分享。
默认规则：

- 有跟踪快照时默认 `检验报告`；
- 无跟踪快照时默认 `因子卡片`，并在报告中显示等待状态。

### FR-4305：移除旧入口

- 不再渲染“因子台账”菜单项。
- 不新增 `/system/alpha-ledger` 到 `/factors` 的重定向。
- 所有内部链接、测试和文档改为新路径。
- 删除旧页面路由和相关过期测试，或将其迁移到新页面契约。

## 3. 因子目录与因子卡片

### FR-4310：结构化因子元数据

每个因子必须具备可被 UI 和 API 消费的结构化元数据：

- `factor_id`
- `display_name`
- `group`
- `direction`：正向、反向或非线性
- `principle`：因子试图捕捉的行为
- `formula`：计算公式或明确口径
- `parameters`：窗口、最小样本数、复权口径等固定参数
- `example`：数值示例
- `data_requirements`：最少历史数据、所需字段
- `caveats`：已知局限、容易受什么影响
- `recommended_tracking`：归一化后的默认回看窗口、主持有期和对照持有期；因子作者可省略覆盖值，由版本化全局默认值补齐，并记录来源

现有 `FEATURE_DOCS` 的“计算 / 含义 / 示例”应迁移或映射到上述字段。新增因子若缺少
必需元数据，因子目录测试必须失败，不能依赖页面兜底猜测。推荐跟踪参数的缺省仅按 FR-4330 在目录归一化阶段处理，不放宽其他必需字段。

### FR-4320：因子卡片内容

因子卡片至少展示：

- 因子 ID、中文名、分组、方向
- 原理
- 计算方式
- 参数
- 示例
- 数据要求
- 注意事项
- 当前覆盖：最新有效标的数、截面样本是否充足、数据截止日期

因子卡片不得只显示一段不可分段的自由文本；至少应把原理、公式、参数和示例分区呈现。

### FR-4321：当前覆盖与数据状态

- 显示最新交易日有多少有效非空因子值。
- 显示截面样本是否达到最小截面要求。
- 数据不足时说明原因，不显示伪造的覆盖率或零值。
- 当前覆盖来自最近一次成功的因子计算或跟踪任务结果。

## 4. 跟踪方案

### FR-4330：系统推荐方案

- 每个因子默认启用自动跟踪。
- 默认跟踪方案来自因子元数据的 `recommended_tracking`。
- 仅推荐参数覆盖值缺省时使用版本化全局兜底：回看 3 年、主持有期 5 日、对照持有期 1/3/5 日、
  买入价开盘价。默认值是可解释的产品起点，不宣称经过最优性校准；保存其版本和来源。
- 首次安装、首次启用或因子版本变化时，系统应在回看窗口内建立跟踪历史；
  建立完成前显示“正在建立跟踪”。

### FR-4331：可配置跟踪参数

用户通过“跟踪设置”覆盖当前因子的跟踪参数：

- `lookback`：`1y`、`3y`、`5y`、`all`
- `primary_holding_days`：`1`、`2`、`3`、`5`、`10`、`20` 中的单选
- `comparison_holding_days`：同一集合中的多选；与主持有期合并去重后的有效集合最多 5 个
- `price_field`：`open` 或 `close`，默认 `open`，放在高级设置
- `bucket_count`：固定 10，不在 UI 暴露
- `universe`：固定全 A 股，不在 UI 暴露
- `min_cross_section`：使用当前统计默认值，不在 UI 暴露

主持有期由服务端加入有效集合并按交易日数排序；超过 5 个时明确拒绝保存，不静默丢弃。
`lookback=1y/3y/5y` 指评价日历区间，右端固定为本轮数据截止交易日 D，左端按 D
减相应自然年后对齐到下一个市场交易日；闰日回退到当月末日。各持有期共用该请求区间，
再分别排除尚未成熟的标签；额外加载的预热数据不得进入统计。`all` 表示数据、上市区间
和预热共同允许的全部历史。报告记录请求区间、实际区间及排除原因。

### FR-4332：单方案约束

- 每个因子最多保存一套自定义跟踪方案。
- 不提供“方案列表”“方案另存为”或多方案并行跟踪。
- 用户可以将自定义方案恢复为系统推荐方案。
- 修改方案产生新的 `profile_revision`，旧快照必须标记为过期或待重算。

### FR-4333：保存与重算

保存跟踪方案后：

- 校验回看窗口、持有期和价格字段。
- 立即将当前快照标记为“配置已变更，等待重算”。
- 尽快触发一次重算。
- 下一个交易日的自动跟踪继续使用新方案。
- 重算期间页面显示状态，不把旧结果当作新方案结果。

### FR-4334：因子定义参数不可修改

用户不能通过跟踪设置修改因子公式中的窗口或参数。需要不同计算口径时：

- 选择另一个已有因子；或
- 在后续版本新增因子定义/因子变体。

本版不提供因子公式编辑器，也不把因子计算参数纳入组合跟踪。

### FR-4335：临时区间转换为滚动跟踪

自定义检验可使用任意固定起止日期；跟踪方案只接受 FR-4331 的滚动窗口。
“设为跟踪方案”必须打开确认表单，展示持有期和价格口径，并要求选择滚动窗口
（可预填系统默认值），明确固定历史日期不会继续作为跟踪边界。
不得暗中猜测窗口或把固定日期存入跟踪配置。保存生成新 revision 并重新计算，
不把临时报告直接发布为跟踪快照；保留来源检验 ID 和选择时间。
这些选择源于历史结果时，报告须说明选择偏差；新跟踪结果也不能自动标成样本外验证。

## 5. 自动跟踪任务

### FR-4340：更新时机

- 自动跟踪在每日行情数据维护完成后执行。
- 任务使用数据就绪检查，避免在日线或交易日历不完整时计算。
- 自动跟踪不是盘中实时任务。
- 任务完成后更新因子总览、因子状态条和报告快照。

### FR-4341：计算与持久化

- 页面请求只读取持久化快照，不在请求路径中计算全市场因子。
- 同一数据快照、周期及因子依赖版本的多个因子共享一次面板/特征计算，再按窗口、
  持有期及因子各自的有效样本掩码计算指标；不得为每个因子每天重复全市场全历史计算。
- 正常更新追加新成熟标签，移出滚动窗口并更新统计；历史数据修订时按受影响区间、
  因子预热依赖及前瞻窗口回算。无法证明增量正确时可有界全算，但不得跳过失效。
- 增量结果须与同一输入的完整重算一致；年度边界、尾部成熟和排除样本均在对拍范围内。
- 跟踪结果包含因子 ID、方案 revision、因子版本、数据截止日、计算时间、
  指标、图表序列和状态。
- 结果持久化到用户配置/数据库目录，不写入源码 checkout。
- 指纹包含因子源码/依赖版本（保留 `FACTOR_VERSION`）、日历/证券池/行情修订版本、
  实际统计参数和预处理版本。只用最新日期或方案 ID 不能识别历史修订。
- 持久化复用逐日 IC/分组汇总与有限图表数据；大面板与临时报告放配置指定的数据目录
  或外部 artifact 目录，不把全市场特征面板塞进账号配置数据库。

### FR-4342：首次/版本变化回填

- 因子首次启用或因子版本变化时，按回看窗口回填历史指标。
- 回填是后台任务，不阻塞因子总览和因子卡片。
- 回填期间状态为“正在建立跟踪”；完成后转为正常。
- 回填失败保留失败原因和重试入口，不能伪装成已完成。

### FR-4343：失败隔离

- 单个因子失败不得导致整个跟踪任务失败。
- 每个因子记录独立状态、错误摘要和最近成功时间。
- 数据不足、因子计算错误、持久化错误和任务取消必须区分。
- 失败结果不覆盖最近一次成功快照；页面同时显示最近成功时间和当前失败状态。

### FR-4344：评价截止日期

每个跟踪快照必须包含：

- `as_of_date`：当前持有期在统计区间内、按可用时间已成熟的最新允许评价日期（信号日）；无有效截面时仍可有此日期，须另报最近有效日期
- `computed_at`：任务实际计算时间
- `holding_days`：该指标对应的持有期

页面对不同持有期分别展示其评价截止日期。不得用 `computed_at` 冒充 `as_of_date`。
具体成熟规则见 FR-4355；不能直接用“最新日减 N”计算。另存 `latest_valid_signal_date`、
当前覆盖日期与 `data_cutoff`，分别表示最近有效截面、因子值覆盖及本轮数据可用边界。

### FR-4345：幂等、并发发布与中断恢复

任务有持久化的 ID、幂等键、配置 revision、输入指纹、租约/所有者及阶段检查点。
同一幂等键的重复触发合并处理；后台计算使用受限并发、时间/内存预算和可取消边界。
每个因子结果完整落盘后原子更新“当前成功快照”指针，不能出现新摘要配旧图表。
发布时重新校验当前 revision、enabled 和输入版本：旧任务晚到只能保留为历史结果，
不能覆盖新配置的当前结果。新数据在计算中到达时，旧快照明确陈旧，并排队新任务。

关闭服务后未完成任务标为 interrupted；重启回收过期租约，从合法检查点重跑或续算。
数据维护成功事件可重复或丢失，启动时必须检查成熟截止日期和积压，不依赖唯一一次回调。
单因子失败与批次状态分开；共享面板损坏可使相关因子分别失败，但不得写伪成功。
失败、取消、数据不足保留最近成功快照和本次状态；暂存结果不成为页面当前结果。

## 6. 检验报告

### FR-4350：报告摘要

报告顶部至少展示主持有期的：

- RankIC 均值
- t 值
- 有效交易日数
- 有效样本数
- D1-D10 平均收益差
- 方向说明：正向、反向或不稳定

摘要必须说明这些指标描述的是因子与前瞻收益的统计关系，不等同于策略净收益。

### FR-4351：图表

报告必须提供以下图表：

1. **RankIC 时序图**
   - 每日 RankIC
   - 20 日滚动均值
   - 零轴
   - 正负值颜色区分

2. **十分位收益图**
   - D1 到 D10 的平均前瞻收益
   - 高亮最低组和最高组
   - 显示 D1-D10 差值

3. **持有期衰减图**
   - 主持有期和对照持有期
   - RankIC 随持有期的变化；t 值可另列，不与 IC 共用一个未标单位的轴
   - 明确各持有期的评价截止日期

4. **年度稳定性**
   - 年份 × IC/t 值的表格或热力图
   - 数据不足的年份显示“—”，不填零

图表可以使用项目已有的 ECharts 能力；本版不引入新的重型图表平台。

### FR-4352：明细表

- 默认折叠。
- 按持有期列出 RankIC、t 值、有效交易日、样本数、D1/D10 收益和差值。
- 年度明细可进一步展开。
- 不再使用因子 × 年份横向铺满的主表。

### FR-4353：指标说明

报告底部必须提供可折叠的“指标怎么读”：

- RankIC 的定义与正负含义
- t 值的含义及未调整序列相关的限制
- D1-D10 的含义
- 持有期和前瞻收益完整性的关系
- 为什么 IC 不等于策略净收益
- 数据不足和样本偏差的影响

### FR-4354：自定义检验

用户可以临时运行一次自定义检验：

- 输入日期区间、持有期和价格口径。
- 结果标记为“自定义检验”，不与自动跟踪快照混淆。
- 运行期间有明确加载/失败状态。
- 可将自定义检验参数保存为当前跟踪方案；保存动作必须显式确认。
- 未点击“设为跟踪方案”时，不修改自动跟踪配置或快照。

### FR-4355：统计、价格时序与成熟样本

以市场交易日序列 `t0,t1,...` 标识日线，因子在 `t0` 收盘后的 `available_at` 可用。
主持有期 h 的研究标签固定为 `P[t(h+1)] / P[t1] - 1`；P 为所选的同口径复权
open 或 close。切换 close 不代表允许在 t0 收盘成交，不启用 cheat-on-close。
收益标签、交易可执行性和成本后净收益分开；报告显示真实价格与复权来源。

标签仅在进出价格及其复权依赖均已可得、退出日数据达到本轮截止要求后成熟。
例如周一信号、周二开盘进入、周三开盘退出，1 日持有期在周二仍不能评价；
若只使用盘后入库的日线，则需周三日线就绪后发布该标签。尾部至少需要 h+1 个
后续交易日价格位置，不能按自然日或直接减 h 推断成熟。交易日跳缺、停牌缺价、
上市/退市和非有限值逐因子/持有期诊断，不向前回填未来价格补造样本。

RankIC 是同日有效证券中因子值与前瞻收益的 Spearman 相关，并列使用平均秩；
Pearson IC、ICIR 与其标准差/年化约定沿用 FR-4009 的明确统计合同。
普通 `t_naive = mean(IC)/(sample_std(IC)/sqrt(n_days))`，少于两日或方差为零时
无定义，不输出 Infinity。UI 标注“普通 t 值，未调整序列相关/多重选择”；审计的
分块统计和检验功效要求仍按 FR-4003，不能以 t_naive 代替审计通过。

D1 为原始因子值最低组、D10 为最高组；固定显示 D1−D10，不因因子方向自动换号。
并列值不强拆；允许空组，缺任一端时差值无定义。分组先算每个信号日的等权平均
前瞻收益，再对可比较日期等权汇总；D1−D10 使用两端均有效的相同日期。
图表和 JSON 标记该日等权口径，不能混用当前可能按证券行数池化的汇总结果。
差值卡上的 D1、D10 均值也须来自端组共同日期，使差值可直接对账。
该口径与现有 `alphatest` 的池化结果不同：新研究结果必须升级 statistics/schema 版本，
提供迁移说明；旧缓存不能改标签后沿用，当前发布版行为和教程在实现前保持原样。
提供 n_rows、有效因子-标签配对数、有效截面数及每组日期/样本数，明确各自含义。

各持有期摘要可使用各自成熟样本，须分别显示 as_of_date 和计数；
持有期衰减主图则使用所有选中持有期共同成熟且有效的信号日期交集，并注明样本范围。
交集不足时显示无法比较，不把不同市场区间的均值连成误导性的衰减曲线。

因子卡片方向为预先声明的经济解释；报告中的方向为样本描述，须区别二者。
非线性因子的零 RankIC 不自动等于无用；不以绝对 t 值、单个符号或历史择优结果
自动宣布有效/无效。多次自定义检验、按结果选择方案须保留研究来源并提示选择偏差。

## 7. 空状态、错误与陈旧状态

### FR-4360：状态集合

因子详情和总览必须区分：

- 未建立跟踪
- 正在建立跟踪
- 正常
- 数据不足
- 计算失败
- 配置已变更，等待重算
- 数据已更新但跟踪未更新
- 自定义检验失败

### FR-4361：陈旧结果

- 按各持有期的交易日/可用时间合同计算应成熟日期；5 日结果自然滞后不等于任务陈旧。
- 区分行情本身未就绪和行情已就绪但跟踪未完成；不可用陈旧行情的最新日期自行证明新鲜。
- 如果跟踪结果的评价截止日期落后于当前应成熟日期，显示相应的数据或跟踪待更新状态。
- 如果方案或因子版本变化，显示“配置已变更，等待重算”。
- 陈旧结果可以继续展示，但必须带明显状态，不得伪装成当前结果。
- 不使用零值填充缺失的 IC、t 值或收益差。

### FR-4362：空状态引导

- 未建立跟踪时，因子卡片仍可正常查看。
- 报告 tab 显示跟踪尚未建立的说明和“立即建立跟踪”入口。
- 首次回填期间允许用户离开页面，后台继续执行。

## 8. 数据模型与接口边界

具体表名和代码结构由实现决定，但必须满足以下语义：

### 8.1 跟踪方案

```text
FactorTrackingProfile

- revision
- enabled
- lookback
- primary_holding_days
- comparison_holding_days
```

### 8.2 跟踪快照

```text
FactorTrackingSnapshot
```

### 8.3 任务接口

- 可以由调度器、管理命令或内部 API 触发。
- 触发接口必须支持单因子重算和全量跟踪。
- 任务必须幂等；同一因子、方案 revision、因子版本和数据指纹的重复执行不得产生
  重复快照或错误状态。
- 任务失败保留结构化错误，供页面和日志消费。

## 9. 非功能要求

### NFR-4301：页面性能

- 因子总览和详情页不得在请求中运行全市场因子计算。
- 有快照时，页面主要渲染持久化结果和有限图表数据。
- 首次回填或自定义检验可以耗时，但必须有状态和超时/取消边界。

### NFR-4302：可复现

- 跟踪结果记录因子版本、数据指纹和跟踪方案 revision。
- 相同输入、相同方案和相同因子版本应产生一致结果。
- 结果过期或配置变化后，旧结果不能继续作为当前结果展示。

### NFR-4303：失败隔离

- 单个因子计算失败不影响其他因子。
- 单次任务失败不覆盖上一次成功快照。
- 页面必须同时显示最近成功和当前失败状态。
- 账号权限、任务状态、已发布结果的有效性分开建模；状态不能仅由“存在快照”推断。

### NFR-4304：存储与路径

- 跟踪配置和快照属于持久化用户数据，使用配置/数据库目录。
- 不得在源码 checkout 中创建运行数据、缓存或报告。
- 临时计算产物遵循项目外部 artifact 目录约定。

### NFR-4305：测试

- 导航顺序、旧入口移除、分组侧栏、双 tab、空状态均有离线测试。
- 跟踪方案校验、单方案约束、方案变更过期、失败隔离和首次回填有单元测试。
- 报告摘要、图表数据结构、数据截止日期、自定义检验和指标说明有渲染测试。
- 使用固定 fixture 和确定性因子版本；不依赖 Tushare、腾讯或真实行情网络。
- 不降低现有复杂度、重复代码、行长度、文件大小和覆盖率门禁。

### NFR-4306：可访问性

- tab 可使用键盘切换，并暴露当前选中状态。
- 图表必须有文本摘要或可访问数据表。
- 状态颜色不能是唯一的信息载体；必须有文字状态。

### NFR-4307：CE 边界

- 因子研究是 CE 能力，不增加真实交易。
- 不把因子研究结果描述为盈利保证或真实交易能力。
- 不加入 millionaire pro 私有风控与三重障碍程序。

### NFR-4308：统计与任务边界

- 持久配置写入、开启/关闭自动跟踪、重算和自定义检验复用已认证的维护权限，不能由无权限页面请求触发批量计算。
- `enabled` 可关闭某个因子的自动跟踪；手动检验独立运行，不暗中重启已关闭的跟踪。
- 审计与普通研究报告使用不同类型/状态，统计结果不能生成 AuditReport 的 PASS。

## 11. 实施里程碑

1. **统计合同与 oracle**：成熟时间、独立样本、日等权/共同样本、版本化报告。
2. **因子元数据与卡片模型**：结构化元数据、卡片分区、覆盖状态。
3. **跟踪方案**：推荐方案、单方案覆盖、保存/恢复、过期状态。
4. **自动跟踪任务**：每日调度、首次回填、增量对拍、原子快照、失败隔离与恢复。
5. **IA 与报告 UI**：一级导航、分组侧栏、总览、双 tab、旧入口移除、摘要和图表/明细。
6. **自定义检验**：临时运行、结果标识、设为跟踪方案。
7. **验收**：离线 fixture、状态矩阵、路径与性能检查。

## 12. 评估后的实施约束

保留一级入口、单方案、双 tab 与后台默认跟踪，避免引入多方案平台。
先冻结统计时序/样本合同和 oracle，再建立版本化任务与持久快照，最后接入完整 UI；
页面骨架可以先做，但不能用占位数值或未审计计算宣称功能可用。

全量共享面板、有界增量与全算对拍用于控制成本；没有本机数据时无需付费联网，
保持等待数据的明确状态。默认参数不是收益推荐，单方案更改可追溯但不增加多方案 UI。
总览用于跨因子定位、状态条用于当前方案、卡片用于原理、报告用于证据，避免重复宽表。
评估依据和合并决定见 [评估记录](../../reviews/2026-11-05/FACTOR-RESEARCH-MERGE.md)。
