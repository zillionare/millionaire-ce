# Mypy 调查与首批修复

## 基线与原因

2026-11-03，原 pre-commit 钩子使用 `mirrors-mypy v2.1.0`，与项目 dev 依赖要求的 `mypy >=1.19.1,<2.0.0` 不一致。钩子在独立环境中运行，镜像默认携带 `--ignore-missing-imports`；项目运行环境直接检查时会额外报告未提供 `py.typed` 或 stub 的第三方包。对未改动前的所有受控 Python 文件运行原钩子：10,079 errors，664 files；其中 6,667 条缺少函数类型标注、1,376 条名称未定义、643 条在已标注代码中调用未标注函数。类别不能直接等价于运行时缺陷：严格标注缺失是可维护性问题；动态框架的星号导入和缺失 stub 可造成名称分析失败；个别报告指向真实的测试或代码问题。

例如 `tests/unit/quantide/web/auth/test_v0204_b08_middleware.py` 有同名测试函数，Python 导入时后者覆盖前者。全仓测试文件共发现 30 个被同名函数覆盖的测试，已重命名以恢复收集，相关测试通过。重复的 `repo` fixture 也已移除其被覆盖的定义。

## 本批改动

- mypy 镜像版本调整为 1.20.2，与项目 dev 依赖的版本约束一致；不改变现有严格配置。
- `server_address.py`、`atomic_files.py` 和 `optimization_forms.py` 补充参数与返回类型；三文件通过 pre-commit mypy 定向检查。
- `StockList` 修复隐式 `None` 默认值及缺失泛型参数，并显式导入框架名称；第三方无类型标记的问题仍需独立处理。
- 截至版本对齐与首批修复后，钩子全仓扫描仍有 10,005 条错误、659 个文件；该数字使用相同 `pre_commit run mypy --all-files` 命令，版本由 2.1.0 切换至 1.20.2，不能把数量变化全部归因于代码修复。

剩余工作应逐模块补齐真实类型契约，修复由此揭露的错误，为确实缺少类型信息的第三方 API 提供经验证的声明或封装，修复测试类型及动态 mock；每批验证类型检查与行为测试。禁止用全局关闭检查、扩大忽略范围或无意义的 `Any` 标注代替修复。全仓通过前，不应声称 mypy 问题已完成。
