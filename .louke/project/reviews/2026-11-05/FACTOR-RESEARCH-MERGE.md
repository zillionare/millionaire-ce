# 因子研究拓展评估与 001/003 合并

日期：2026-11-05。评估对象：新增 003 的 story/spec 与既有 001 的审计、归因和月线规划。
本次修改仅涉及规划和路线图，不实现功能，不改变当前包版本或发布条件。

## 结论

拓展方向合理，纳入 001。一级因子入口、分组目录、结构化卡片、报告双 tab、
单方案和自动跟踪补齐了原 FR-4009 只有研究内核而缺少持续使用路径的问题。
单方案适合作为首版边界；多方案、因子组合和盘中评估继续不做。

本次没有把 003 原样拼接后宣称完成：原稿主要描述产品体验，统计时序、异步状态和
验收可执行性仍有缺口。以下问题已在合并规格中补齐，并增加对应 AC 和测试计划。

## 评估与处理

| 问题 | 原稿风险 | 合并决定 |
| --- | --- | --- |
| 日线标签成熟 | “至少滞后 h 日”不足以定义当前 open 口径；t1 进入、t(h+1) 退出多一个位置 | 固定交易日/available_at 合同；按每持有期求成熟日，单列最近有效日期与覆盖日期 |
| 衰减图比较 | 不同持有期的截止与有效日期不同，可能把市场区间差异当作持有期差异 | 摘要按各自成熟样本；衰减主图按共同有效日期，显示交集及每持有期样本量 |
| 分层统计 | D1−D10 没有固定排序、样本权重或缺端规则 | D1 最低/D10 最高；日内等权后日间等权，端组同日比较；明确不同于现有池化实现，升级统计版本 |
| 显著性与方向 | 普通 t 值受重叠收益与研究择优影响；非线性因子可有近零 RankIC | t_naive 和审计统计分开，保留选择来源；不凭阈值自动宣布有效，不称样本外或收益保证 |
| 自定义转跟踪 | 任意固定区间无法无损保存为只支持滚动窗口的 profile | 显式确认滚动窗口，生成新 revision 并重算；不复制临时报告为当前快照 |
| 默认参数 | “元数据必须有推荐参数”与“缺失时兜底”冲突 | 作者覆盖值可省，目录归一化后必须有有效默认和版本来源；不放松其他元数据 |
| 持有期上限 | 对照最多 5 个但自动加入主值可能变成 6 个 | 合并去重后最多 5 个，超过就拒绝，不静默删值 |
| 后台发布 | 幂等不足以处理改配置后旧任务晚到、断电、重复或丢失事件 | 持久任务/租约、版本校验、原子发布、启动补查及失败保留；恢复不发布部分结果 |
| 性能与数据修订 | 每个因子每日完整重算 3～5 年成本高；只看末日不能识别历史修订 | 共享面板、有界增量/受影响回算、完整重算对拍；数据/日历/证券池/统计版本入指纹 |
| 状态解释 | 正常成熟滞后、行情陈旧、跟踪未更新和最近失败容易混为一谈 | 配置、最新尝试、最近成功、有效性分离，页面组合明确状态 |
| 周期与扩展 | 原 001 允许自定义因子/周期，003 固定全 A 股日线及目录 | 研究内核继续可接未登记面板；自动跟踪 UI 首版固定日线/全 A 股，注册后跟踪；月线仍按独立合同 |
| CE 范围 | 原故事导航例子直接展示实盘，与 CE 范围矛盾 | CE 导航无实盘，millionaire pro 按能力开关显示 |

普通研究的“有相关性”、代码审计的 PASS 和策略净收益是三类证据；合并后的文档
分别定义，避免自动跟踪状态“正常”被用户误解为“因子已审计/能盈利”。

## 可实施性与工作量

可复用 `quantide.factors.alphatest`、catalog、现有图表及数据维护基础，但不能仅换 UI：
当前研究输出缺少完整的带日期序列、成熟时间/样本诊断和可恢复的跟踪状态。
需要统计内核合同、版本化持久任务与快照、目录元数据、研究 UI 四部分协同。

全量自动跟踪是本次拓展的主要资源成本。举例，5,000 证券×750 交易日×28 个
float64 特征，单数值矩阵已约 840 MB（不含索引、价格、临时副本和图表）；
这是规模估算而非性能验收。首版需共享特征面板、分阶段/有界计算和可取消回填，
用固定资源 fixture 建立预算；不能声称“极简”就忽略后台成本。

建议按统一里程碑先完成统计/oracle 与结果模型，再做任务/恢复和完整 UI。
UI 骨架可以提前并行设计，但不代表后台正确性已交付。001 现覆盖更多完整能力，
因此计划范围已增大；本次不臆定工期，也不将这些新功能塞进当前版本的发布门槛。
