## 二、已确认的修复

以下结合代码、新增回归测试及独立复现确认：

- 默认使用内部截断点；显式选最后日期且无未来行时为 INCONCLUSIVE。

- insufficient 保留最近成功快照并记录本次不足状态。
- 两个生产研究入口显式传权威交易日历，原“全市场缺日被压缩”调用缺口已修复。
- 迟于入场日的因子被排除；但入场日内的精确可用时刻仍有问题，见 F5。

- 结果 diagnostics 记录 min_cross_section；coverage 字段改名；年度 t 值、概览入口、tab 的 aria-current 和指标排序已补入。

## 三、仍未关闭的实施问题

### F1 · P1：无有效历史证据或没有实际改变输入，仍可 PASS

位置：`quantide/audit/future.py:208–247,263–264`，`quantide/audit/checks.py:45–71`，`quantide/audit/factor.py:141` 的 schema 成功返回。

当前只新增“未来行数为零”检查。`perturbed_rows` 统计的是 available_at 晚于 cutoff 的候选行数，既不保证数值真的改变，也不保证被比较的历史输出包含有效因子值。

独立复现：

1. 3 天 × 3 资产输入审计 `ma20_slope`：该因子有效输出数为 0，整体状态仍 PASS。
2. pipeline 总是返回 `head(0)`：未来行真实存在，未来不变性仍 PASS。
3. 数值 x 全为 0，仅请求 zero 模式：输入实际完全不变，仍 PASS。

这是上一轮“证据缺失不得 PASS”问题的未关闭部分，违反 FR-4001 中“预热中无输出不能记为通过”和审计证据合同。不能仅把默认 cutoff 移到样本中间就认为关闭。

建议：分别记录候选未来行数、实际变更单元数、历史比较行数和有效输出数；按预热/缺失合同判断是否有充分可比较输出。无证据返回 INCONCLUSIVE；新增上述三个负例。合法缺失值掩码仍需比较，不应粗暴删除所有 null。

### F2 · P1：显式 AuditSpec 仍未绑定实际输入和完整执行配置

位置：`quantide/audit/factor.py:326–340`。

显式 spec 只验证 object_id、cutoff 和部分种子，未验证 data_hash、source_hash、模式和 positive_columns 等有效配置，然后直接沿用调用者 spec。

独立复现：从原始面板生成 spec，先审计原数据，再把所有 close 乘以 1.01、模式改为仅 extreme，仍传旧 spec。第二次返回 PASS；两份报告 fingerprint 相同，第二份报告 data_hash 与实际输入摘要不符。

影响：上轮 R3 只在自动生成 spec 的路径修复。报告仍可证明错误的数据/配置，缓存与重现不可信。

建议：解析完整执行参数后生成期望 spec，验证所有影响执行/身份的字段，或以实际输入重新生成权威 spec 并拒绝不一致声明；测试数据、模式、源码/依赖版本和扰动字段分别改变的情况。

### F3 · P1：数据 hash 仅被存储，未参与来源失效与发布时的输入版本校验

位置：`quantide/service/factor_tracking.py:280–314,490–534,699–713`。

新增 data_hash 等字段是进展，但 `_view_status` 只比较最新日期；`_publish_snapshot` 只校验配置版本及 data_cutoff 的大小；启动补查也只判断日期。没有拿当前输入版本与快照输入版本比较。

独立复现：相同配置、相同 2026-11-06 截止日，先发布 revised-market 的快照，再让 old-market 输入的结果晚到。后者覆盖 current，页面状态 normal。不同 idempotency_key 只能识别“不同”，不能识别“哪份输入已失效”。在正常单实例触发去重之外，输入在计算期间修订、直接刷新调用或多进程也需要这一发布保证。

更常见的单实例情况也不依赖并发：历史行情已修订但最后日期没变，用户查看快照时仍显示 normal，直到另一次主动重算；新 hash 只有重算时才产生，无法承担即时失效检测。

建议：由数据维护层提供持久且单调/可比较的快照版本或来源 manifest；创建任务、失效判断和原子发布均绑定它。新版本到达应明确陈旧并排队，不能按日期相等接受旧输入。不要在每次页面读取中重新计算全市场 hash。

### F4 · P2：calendar_version 不是内容指纹，等长度日历修订会碰撞

位置：`quantide/service/factor_study.py:36–37`，由跟踪快照和自定义研究共用。

当前值仅为“首日:末日:数量”。例如 `{11-02,11-03,11-06}` 与 `{11-02,11-04,11-06}` 都是 `2026-11-02:2026-11-06:3`，但对应持有期标签不同。

这不能满足 FR-4341 的日历修订指纹合同。即使 F3 增加版本比较，当前日历版本仍无法识别该修订。

建议：对规范化完整交易日序列计算稳定内容摘要，或使用有同等保证的权威日历 revision；测试边界不变且总数不变的内部日期替换。

### F5 · P1：入场日午后才可用的因子仍可用于当日开盘入场

位置：`quantide/factors/research.py:317–323,452–457`。

修复新增“available_at 不晚于入场日”的条件，但 `_late` 将 datetime 截成 date。默认 price=open 时不能据此判断开盘前是否已知。

独立复现：11-02 信号，11-03 开盘入场，因子实际可用时间为 11-03 14:00。提供权威日历和明确 available_at，3 个资产仍全部计入有效样本。

影响：上轮 R4 的跨日反例已修复，同日时刻边界仍有前视。不能因研究 UI 是日线就丢弃输入提供的精确可用时间。

建议：根据 open/close 和策略决策合同确定交易所时区的决策时刻；按完整 timestamp 比较。只有 date 的数据须定义保守可用约定；补开盘前、开盘后、收盘后及跨时区样本。

Ruff/行宽通过。应重构逻辑和共享类型定义，不能放宽预算或忽略告警。
