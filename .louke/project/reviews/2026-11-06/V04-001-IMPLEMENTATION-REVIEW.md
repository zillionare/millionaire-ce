日期：2026-11-06。审查对象：基于 `b790c71` 的当前工作区未提交实施，包括新增 audit、因子研究、跟踪服务和 Web 页面；不是只审查已提交 HEAD。

## 结论

**建议请求修改，不能据此宣布整个 v0.4-001 完成。** 原报告提出的三个主要阻断项成立；独立复现还发现了时间精度、历史可用性、交易日历、报告指纹和配置竞争等问题。部分问题会使有错误的数据或实现获得 PASS，直接影响这项功能作为 AI 因子/策略质量门禁的可信度。

本次没有修改实施代码或放宽规格。下文 P1 表示合并前应修复的正确性问题，P2 表示需要补齐的功能或可靠性问题，P3 表示较低优先级的展示问题。若决定分阶段合并，必须明确交付范围及未完成 AC，不能通过修改完成声明把缺口视为通过。

## 二、独立发现与复现

以下在离线、隔离配置下复现，未使用真实行情、Token 或账户。每项应加入对应回归测试，不能仅修改本次示例的期望值。

### R1 · P1：30 分钟未来数据因日期截断漏检

- 位置：`quantide/audit/future.py:48–63`。
- `_day()` 把 datetime 变成 date，再比较 available_at 与 cutoff；同一天的后续 bar 不再是“未来”。
- 复现：同日 10:00、10:30、11:00 三行，值为 1、2、3；cutoff=10:30。被测 pipeline 故意使用全样本均值作为历史信号。审计返回 PASS；单独将 11:00 的值改为 99，历史信号由 2 变成 34。
- 影响：明确有前视的 30 分钟实现可通过未来扰动审计，违反 FR-4002/AC-4002，且不只是默认 cutoff 的问题。
- 修复验收：按声明的时区和精确时间比较；同日后续 bar、跨时区、收盘边界分别测试。日线 date 输入也应有明确语义。

### R2 · P1：重复资产/日期键可通过 schema 及整体审计

- 位置：`quantide/audit/factor.py:39–59`。
- schema 仅校验列存在、因子名及输出列存在，没有验证主键唯一性等数据合同。
- 复现：45 天 × 3 资产的正常输入额外复制首行，以中间日期作为 cutoff、使用 `bias_5`。`factor.schema=PASS`，整体报告也 PASS。该案例有实际未来数据，不依赖默认末日空扰动。
- 影响：重复行情可改变窗口与权重，却获得“数据契约通过”的证明，违反 FR-4001/AC-4001。
- 修复验收：重复键必须明确 FAIL 并报告位置；补充类型、顺序、单位及 availability 合同的负例。research 内部已有重复键拒绝，不能据此认为 audit 入口也已覆盖。

### R3 · P1：实际审计 cutoff 改变，报告指纹不变且记录错误

- 位置：`quantide/audit/factor.py:88–108,127–149`。
- 构造 spec 时记录输入最大日期，随后才解析实际 cutoff；实际参数未完整绑定到 spec/config 指纹。
- 复现：相同输入分别使用 2024-01-21、2024-01-31 截断。两份报告 fingerprint 相同，记录的 truncation_points 均为 2024-02-14。
- 影响：无法准确复现报告，也无法用指纹区分不同审计；报告存储/缓存可能错误复用，违反 FR-4008/AC-4013。
- 修复验收：先解析完整执行配置，再生成指纹；绑定实际截断点集、种子、扰动字段/模式及其他有效参数。显式提供 spec 时需验证与执行一致。`FACTOR_VERSION` 本身确实来自源码 hash，本项不是指责它只是手写常量。

### R4 · P1：事后才可用的因子被回填到更早的决策中

- 位置：`quantide/factors/research.py:305–309`。
- 因子行的 available_at 只与本次研究 `data_cutoff` 比较，没有与该信号的实际决策/入场边界比较。
- 复现：信号日 2026-11-02，按合同 11-03 入场、11-04 退出；该因子到 11-05 才可用。研究截止 11-06，提供正确交易日历，3 资产仍全部成为有效因子/标签对。
- 影响：事后发布或修订的因子可获得不可交易的历史 IC。标签成熟与因子历史可用性是不同条件，不能用一个 evaluation cutoff 代替二者。
- 修复验收：明确决策可用时刻；迟于入场甚至退出的因子必须排除或按明确合同移到未来信号日，并统计排除原因。正常“收盘后可用、次日入场”的因子应保持有效。

### R5 · P1：配置 revision 可回退、并发丢增量，旧任务可成为当前结果

- 位置：`quantide/service/factor_tracking.py:180–208,370–387`。
- `reset_profile()` 删除持久配置，返回默认 revision=0；save 的读当前 revision 在 `_PROFILE_LOCK` 外。发布校验与写入也不是覆盖配置变更的同一原子操作。
- 复现 A：默认 revision 0 → 保存变 1 → 重置回 0；重置前持有默认 revision 0 的旧任务随后成功发布为 current。
- 复现 B：并发两次 save，在读取当前配置后同步放行，两者均返回 revision 1，最终持久值也是 1，而非严格递增到 2。
- 影响：原报告所称 revision 递增/版本竞争只覆盖部分路径；FR-4332/4345、AC-4314 尚不满足。
- 修复验收：reset 也是一次持久的单调版本变更；读改写、版本校验及 current 指针更新需要事务或同等原子机制。测试 save/save、save/reset、计算中 reset 和发布瞬间配置变化。

### R6 · P1：生产研究入口未传权威日历，全市场缺日时持有期被压缩

- 位置：`quantide/factors/research.py:246–253`；调用处 `service/factor_tracking.py:324–335`、`service/factor_study.py:85–98`。
- research 支持显式 calendar；缺省使用面板实际出现的日期。两个生产入口都没有传权威市场日历，因此某交易日全市场数据缺失时被当成不存在。
- 复现：权威交易日为 11 月 2/3/4/5/6 日，3 资产面板全部缺 11-04。11-02 信号、h=1、截止 11-05：缺省得到 3 个有效对，相当于用 11-03→11-05；传权威日历得到 0 个，因正确退出日 11-04 缺行情。
- 影响：数据缺失会悄悄改变收益标签时间跨度。仅检查现有行里有没有空价无法发现此问题。
- 修复验收：生产入口传版本化权威日历并检查数据就绪；缺整个交易日应报诊断/不足，不能跨越缺口自动缩短交易日序列。

### R7 · P2：数据不足的刷新覆盖最近成功快照，并记录为 succeeded

- 位置：`quantide/service/factor_tracking.py:370–387`。
- 发布路径不检查 snapshot 的计算状态，只要配置相符就替换 current 并写 succeeded。
- 复现：先发布 status=ok 的成功快照，再发布 status=insufficient，current 被替换为 insufficient，last_attempt 为 succeeded，原成功结果丢失。
- 影响：违反 FR-4345 保留最近成功快照的要求。异常时保留旧结果的测试不能证明数据不足时也正确。
- 修复验收：分开“最近成功快照”和“本次尝试”；不足、失败、取消不覆盖成功指针，页面同时显示旧结果时间及本次状态。

### R8 · P2：统计接口接收的参数没有真正执行

- 位置：`quantide/audit/statistics.py:89–99,109–127,130–159`。
- `null_rank_ic_distribution()` 仅循环 seeds，忽略 `StatisticalProfile.permutations`。复现 seeds=(1,2)、permutations=100，实际只生成 2 个零分布样本。报告可以同时携带配置 100 与结果数 2，并在未检查预定功效时返回 OK。
- `rank_ic_summary(forward_col=...)` 校验指定列后，调用的 `daily_rank_ic` 仍读取硬编码 `forward`。只有 `ret` 列且指定 forward_col="ret" 时，抛出 `ColumnNotFoundError: forward`；两列并存时还可能读错标签。
- 影响：统计参数和结果口径不一致，不应作为预注册对照已完成的证据。
- 修复验收：明确种子集与每种子置换数的合同，实际执行并记录数量；有效样本及功效不足明确 INCONCLUSIVE。测试仅含自定义标签列，以及默认列和自定义列故意不同的场景。

### 对原意见 #2/#12 的额外实证：未定义指标被绘成零

`web/pages/factors.py:312–321` 的 `or 0` 将缺失 RankIC 均值、缺失分层收益填成数值 0。构造 `mean=None` / `mean_forward=None` 时，生成的图表数据确实为 `[0]`，不是空缺。

另外，将各持有期全样本均值设为 0.9/0.8、共同样本均值设为 0.1/0.2，当前图输出 90/80，合同要求的是 10/20（百分数展示）。应使用共同样本，并保留 null/缺失状态；有效零值仍显示 0。这与合法零计数是不同问题。
